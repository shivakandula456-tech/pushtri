# Data sources and access policy

## Intended source

The only intended source is the public racecards section of AT The Races (`https://www.attheraces.com/racecards/...`). No other source is configured, and the site never fetches anything from the browser — the static frontend reads only files inside this repository plus data stored locally by the user.

## What was observed (2026-10-18)

- `robots.txt` was fetched successfully. For `User-agent: *` it disallows `/ajax/`, `/userlogin/`, `/user/login`, `/userprofile`, `/festivals/*/userprofile*` and any URL containing `showResult=yes`. Paths under `/racecards/` are **not** disallowed. The exact snapshot is kept at `collector/fixtures/atr-robots-observed-2026-10-18.txt`.
- Direct automated GET requests to `https://www.attheraces.com/racecards` and `https://www.attheraces.com/racecards/2026-08-15` returned **HTTP 403**. Automated access is currently blocked by the site's protection layer.

## Policy

- Bot protection is **never** bypassed: no header spoofing beyond an honest user-agent, no proxies, no challenge solving.
- The collector hard-stops on 401/403/429 responses and on challenge/interstitial pages, publishes nothing, and reports the block.
- All network modes are disabled by default. The scheduled workflow runs only the offline self-test. Network modes require the repository variable `COLLECTOR_ENABLED=true`, which is documented as being set only after written permission is obtained and a probe run is reviewed.
- `data/indexes/status.json` records the permission situation (`permissionStatus: "blocked_http_403_observed"`) and the notes above, and the dashboard surfaces them.

## What is in this repository today

Only synthetic test fixtures. Thirteen fixture races under `data/fixtures/races/` were generated by `test-fixture-generator-1.0.0`; they are flagged `testData: true` everywhere, are excluded from backtests unless explicitly opted in, and are never presented as collected data. The published dataset is empty (`datasetStatus: "not_collected"`).

## If access is approved later

1. Obtain written permission from the source.
2. Confirm robots.txt still allows the racecards paths.
3. Run `--probe` locally or via workflow dispatch (requires `COLLECTOR_ENABLED=true`) and review the saved HTML and parser report under `collector/.probe/`.
4. Only if the probe is clean: set `COLLECTOR_ENABLED=true`, dispatch a bounded `--dry-run`, review the run report, then allow `--live`.
5. Update `status.json` so `parserValidatedAgainstLive` only flips to `true` after a successful live parse of real pages. Until that happens it stays `false`.

The historical window 2026-08-01 → 2026-08-15 is the research target, but whether the source exposes those dates to an approved collector is unverified and is one of the things the probe must establish.
